Once Claude is writing substantial pieces of an implementation, the difficult part is deciding whether the result does what we intended. Reading more generated code can become another queue. The harness gives us a way to carry decisions into the work and get useful feedback while it happens.

This 14-slide deck introduces six habits using small examples of the files and commands involved: planning with `/plan`, giving Claude meaningful checks, keeping project instructions concise, configuring access, using a separate reviewer, and automating recurring work with skills and hooks.

## Use it with your team

Bring a repository and a change you can explain. As you work through the slides, identify what Claude would need to know, what it could run to check the result, and which decisions still need a conversation. Start with the gap you actually have.

The PowerPoint includes my speaker notes for every slide so you can lead the discussion without me. The PDF is a copy of the slides for reading or sharing. The examples need your project's commands and conventions.
